# 论题：代码不能表达意图

## 一句话

> intentflow 不试图从代码里「提取意图」。它做的是：用 IR 算出**确凿的事实**，让 LLM 在事实之上做**可回查的推断**，并把这个推断的**可信度**显式摆在人面前。

## 前提

**代码里没有「意图」。**

意图存在于写代码的人脑子里、PR 描述里、issue 里、会议记录里。代码只有结构：谁调谁、数据从哪来到哪去、边界在哪。

推论：

| 问题 | 代码里有答案吗 | 谁能回答 | 可信度 |
|---|---|---|---|
| 这个函数调了 `db.Query` 吗 | 有 | 编译器 / IR | 可验证 |
| 数据从 HTTP 参数流到了 `db.Query` 吗 | 有（可达性） | SSA 数据流 | 可验证 |
| 这条路径是这次 PR 新加的吗 | 有（双边 IR 做差） | 编译 + diff | 可验证 |
| 为什么要加这条路径 | **没有** | LLM 推断 + 人确认 | 不可验证 |
| 这样写合不合理 | **没有** | LLM 推断 + 人判断 | 不可验证 |

后两行不在代码里。**任何声称从代码里「提取意图」的工具，都是在猜，只是没说自己是在猜。**

## 由此推出的三条设计约束

### 1. LLM 不能发明事实

LLM 说的每一句结构性断言，必须能映射到一条 IR 事实。否则丢弃。

实现：LLM 的输出格式里，每条 `finding` 必须带 `evidence: [fact_id]`。没有 evidence 的 finding 直接判无效。

### 2. 事实层和推断层必须分行显示

不能把「IR 算出来的」和「LLM 猜的」混在一段文字里。否则人类无法判断该信哪部分。

实现：可信度标签 `EXTRACTED / DERIVED / INFERRED / ASSERTED / UNKNOWN`，每一条结论都带标签，界面上用不同样式区分。

### 3. 上层结论必须能往下钻

人类看到「这次改动新增了一条用户输入直达 SQL 的路径」，要能点开看到具体是哪条边、哪个文件、哪一行。

实现：每个 finding 挂 `path`（数据流路径）+ `location`（文件:行）。Web 端可点开。

## 为什么这三层 diff

| 层 | 内容 | 来源 | 可信度 | 有用度 |
|---|---|---|---|---|
| **L3 项目结构 diff** | 包/模块依赖变化、分层违反 | import graph | 高 | 低 |
| **L2 逻辑结构 diff** | 调用图变化、数据流路径增删、控制流变化 | SSA + SyntaxFlow | 高 | 中 |
| **L1 意图 diff** | 这次改动的语义变化是什么 | LLM 基于 L2/L3 推断 | **低** | **高** |

注意这个反比：**越确定的层越没用，越有用的层越不确定。**

这不是缺陷，是分工。L3/L2 存在的意义不是自己有用，是给 L1 提供锚点。

## 与已有项目的分野

所有相关项目都在解决「人看不懂代码改动」或「Agent 写的代码不可控」。分野在于**谁做分析**：

| 做法 | 代表 | 分析可信度 |
|---|---|---|
| 提示词约束 | ub-mode | — |
| 外部 linter + 队列 | desloppify | 规则可复现，但只覆盖语法级 |
| LLM 读代码写 JSON | pr-lens, archify | 结构可校验，**语义不可校验** |
| AST 抽图 + 标注可信度 | graphify | 代码部分可复现，**但只到「谁调谁」，没有数据流** |
| **IR 抽事实 + LLM 推断 + 挂锚点** | **intentflow（本项目）** | **事实可复现，推断可回查** |

graphify 是最接近的先例，已经证明「边标 EXTRACTED/INFERRED」这个机制成立。它缺的是数据流深度 —— tree-sitter 只能看到语法层，看不到 `r.URL.Query().Get("name")` 怎么流到 `db.Query(query)` 里。

这正好是 SSA 的强项。

## 待验证的假设

本实验要回答的问题，按优先级：

1. **SSA 双边编译做 diff，能不能稳定得到有意义的「逻辑结构变化」？** —— 技术可行性
2. **把结构化 diff 喂给 LLM，产出的意图叙述比「直接把 diff 给 LLM」好多少？** —— 价值假设，需要 A/B
3. **可信度标注会不会真的让人改变判断？** —— 产品假设，需要人测
4. **Go 之外的语言，这套还得起来吗？** —— 扩展性
