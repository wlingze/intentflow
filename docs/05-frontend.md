# 工作台交互：图、代码、详情，各就各位

> 行为图的语义见 [07-behavior-model.md](07-behavior-model.md)，数据契约见 [08-contract.md](08-contract.md)。

## 1. 问题

旧版把代码放在右侧抽屉。抽屉一开，图被遮住；缩略图浮在代码左下角，又小又挡字。评论栏在两个视角里都需要，但没有任何一个视角能同时容纳三样东西：

- 这次改动在行为上做了什么。
- 具体哪一行、哪个条件。
- 这条结论的证据和风险。

所以拆成两个主视角，每个视角只保留一个次要视图。

## 2. 行为图视角

```text
┌──────────────────────────────────────────────────────────────┐
│ top bar: branch labels · stats · 行为图/代码 · theme · 提交   │
├────────────┬──────────────────────────────────┬──────────────┤
│ 项目改动   │ 01 handleSearch → SQL 执行        │ AI /         │
│ 目录树     │    IN → ?? → ƒ → ?? → OUT         │ SyntaxFlow / │
│ +文件      │ 02 handleSearch → 文件读写        │ Review       │
│            │    IN → ?? → ƒ → OUT              │              │
│            ├──────────────────────────────────┤              │
│            │ 节点详情 + 源码（可拖高/收起）    │              │
├────────────┴──────────────────────────────────┴──────────────┤
│ composer                                                     │
└──────────────────────────────────────────────────────────────┘
```

### 2.1 每条 scenario 一行

一行就是一条行为：触发 → 判定 → 变换 → 效果。

- 行内节点按 `scenario.nodes` 从左往右排，不再把所有节点塞进全局阶段列。
- 不同行之间不连边。`handleSearch` 的守卫只属于 SQL 行和文件行各自的路径，不会横着连到另一条行为的步骤。
- 数据边跨过判定节点时从下方绕行，标签（`format` / `concat`）贴在弧线上。
- 调用边和判定路径同时存在时，只画判定路径；调用关系仍留在 JSON 里。
- 行头写 scenario 标题、delta、来源和形态。左侧项目树负责宏观改动。

为什么不做全局 DAG：旧版把 `findUser` 和 `loadTemplate` 都放在「变换」列，守卫的「继续」边同时指向两者，看起来像一条分叉。实际上它们是两条独立行为。行布局消除了这个假分叉。

### 2.2 底部代码坞

点击节点或边，底部出现详情坞：

- 左栏：角色、delta、文件行号、函数、来源、形态、所属 scenario、证据。
- 右栏：目标行前后 6 行源码，目标行高亮。
- 「引用到评论」把这段代码加入 composer。
- 「打开代码」切到代码视角并定位。
- 顶部有拖拽条，可调高度；右侧关闭按钮收起。

点击节点只打开详情，不自动切代码。这是「点击是详细信息，不是代码」的直接落点。

### 2.3 项目改动树

左栏是目录树，不是平铺事实列表。

- 目录显示聚合 `+行数 / −行数 / 变更文件数`。
- 顶部有增/改/删的构成条。
- 默认只看变更文件；可以切换全部。
- 结构事实和调用事实的数量写在标题下方，供宏观判断。

## 3. 代码视角

```text
┌──────────────────────────────────────────────────────────────┐
│ top bar                                                      │
├────────────┬──────────────────────────────────┬──────────────┤
│ 行为导航   │ 文件 tab · Diff/搜索 · 分栏/统一 │ AI /         │
│ 01 flow    │                                  │ SyntaxFlow / │
│ 02 flow    │ 全宽 diff / 搜索                 │ Review       │
├────────────┤                                  │              │
│ 变更文件   │                                  │              │
├────────────┴──────────────────────────────────┴──────────────┤
│ composer                                                     │
└──────────────────────────────────────────────────────────────┘
```

- 左上是行为导航：每条 scenario 一行流程，点步骤直接跳到文件行。
- 左下是变更文件树；不再重复项目结构事实。
- 没有悬浮缩略图。行为图就是侧栏里的流程列表。
- 选中代码 → 浮动「添加评论」→ 引用进入 composer。

## 4. 右侧：AI / SyntaxFlow / Review

三个 tab：

- **AI**：LLM 摘要、优先复核、风险判断。状态为 `ok` 时显示；未配置时显示环境变量说明。LLM 只读事实。
- **SyntaxFlow**：逐条关注点，认为没事 / 认为有问题 / 已忽略。
- **Review**：评论卡片，可改可删；每条带引用。

默认打开 AI tab（有摘要时），否则打开 SyntaxFlow。

## 5. 状态

```ts
interface AppState {
  view: 'graph' | 'code';
  rightTab: 'ai' | 'signals' | 'review';
  selected: { kind: 'node' | 'edge'; id: string } | null;
  peek: { open: boolean; nodeId?; edgeId?; file?; line?; side? };
  code: { files; active; mode; layout; line?; side?; search };
  comments; dismissed; kept;
}
```

- 评论/忽略/保留写 `localStorage`，key 是 `intentflow.review:<before>-><after>`。
- 节点选择在图上跨行保留高亮。
- 代码坞高度是组件状态，不持久化。

## 6. 数据流

```text
Go: SSA 一次编译
    → 项目/逻辑/意图事实
    → 行为图（scenario 行）
    → payload.Build（before/after 源码）
    → 可选 LLM 摘要
    → GET /api/payload
React: fetch → layoutBehavior（按 scenario 分行）
        ├─ 点击节点 → 底部代码坞
        ├─ 拖拽 → 调高度
        ├─ 打开代码 → 代码视角
        └─ 提交 → POST /api/review → review.md
```
