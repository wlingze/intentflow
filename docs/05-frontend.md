# 工作台交互：图、代码、详情，各就各位

> 行为图的语义见 [07-behavior-model.md](07-behavior-model.md)，数据契约见 [08-contract.md](08-contract.md)。

## 1. 问题

旧版把代码放在右侧抽屉。抽屉一开，图被遮住；缩略图浮在代码左下角，又小又挡字。评论栏在两个视角里都需要，但没有任何一个视角能同时容纳三样东西：

- 这次改动在行为上做了什么。
- 具体哪一行、哪个条件。
- 这条结论的证据和风险。

所以拆成两个主视角，每个视角只保留一个次要视图。

## 2. 函数关系图 + 底部内部行为

```text
┌──────────────────────────────────────────────────────────────┐
│ top bar: branch labels · stats · 行为图/代码 · theme · 提交   │
├────────────┬──────────────────────────────────┬──────────────┤
│ 项目改动   │ 函数调用关系图                    │ AI /         │
│ 目录树     │ 拖拽/缩放/适应                    │ SyntaxFlow / │
│ +文件      │ 点函数 → 下边栏内部路径           │ Review       │
│            ├──────────────────────────────────┤              │
│            │ 内部行为: 触发→判定→变换→效果     │              │
│            │ 右栏: 对应源码                     │              │
├────────────┴──────────────────────────────────┴──────────────┤
│ composer                                                     │
└──────────────────────────────────────────────────────────────┘
```

### 2.1 一屏只画函数调用

- 一个函数一个节点：按 `file + function` 合并触发/变换/效果角色。
- 主图只保留函数之间的调用边；判定和数据边放到下方内部行为。
- 文件不再是画布上的框或列。文件名写在节点第三行，节点位置只看调用关系。
- 没有 `文件 / 函数 / 行为` 三个 tab；主图永远是函数关系图。
- 打开页面时自动适应画布；也可以拖拽平移、滚轮缩放、点「适应」。

### 2.2 布局和边

- 节点先按网格初始化，再用调用边做弹簧收缩，最后做矩形碰撞分离。
- 同一个文件的函数不会被排成连续块；它们按调用关系散开。
- 边用障碍物网格寻路，绕开节点卡片；不再用一条大曲线穿过卡片。
- 边标签默认隐藏，鼠标移到边上才显示；减少 `调用` 文本堆积。
- 新增/移除/变化/未变仍用颜色和图例区分。

### 2.3 底部下钻：函数内部行为

点击函数节点，底部展开该函数的内部行为：

- 左栏按 scenario 列出：触发 → 判定 → 变换 → 效果。
- 同一入口的多条 scenario 各占一条路径，不合并成一条假路径。
- 点路径里的任一步骤，右栏跳到对应源码行。
- 右栏默认显示所选函数自身的节点行，不跳到别的函数。
- 「引用到评论」加入 composer；「打开代码」切到代码视角。
- 顶部拖拽条调高度；右侧关闭按钮收起。

边没有内部路径时，仍打开原来的代码坞模式。

### 2.4 项目改动树

左栏是目录树，不是平铺事实列表。

- 目录显示聚合 `+行数 / −行数 / 变更文件数`。
- 顶部有增/改/删的构成条。
- 默认只看变更文件；可以切换全部。
- 结构事实和调用事实的数量写在标题下方，供宏观判断。

## 3. 代码视角

```text
┌──────────────────────────────────────────────────────────────┐
│ top bar                                                      │
├────────────┬──────────────────────────────────┬──────────────┤
│ 行为导航   │ 文件 tab · Diff/搜索 · 分栏/统一 │ AI /         │
│ 01 flow    │                                  │ SyntaxFlow / │
│ 02 flow    │ 全宽 diff / 搜索                 │ Review       │
├────────────┤                                  │              │
│ 变更文件   │                                  │              │
├────────────┴──────────────────────────────────┴──────────────┤
│ composer                                                     │
└──────────────────────────────────────────────────────────────┘
```

- 左上是行为导航：按触发函数分组；组内展开同源 scenario，点步骤直接跳到文件行。
- 左下是变更文件树；不再重复项目结构事实。
- 没有悬浮缩略图。行为图就是侧栏里的流程列表。
- 选中代码 → 浮动「添加评论」→ 引用进入 composer。

## 4. 右侧：AI / SyntaxFlow / Review

三个 tab：

- **AI**：LLM 摘要、优先复核、风险判断。状态为 `ok` 时显示；未配置时显示环境变量说明。LLM 只读事实。
- **SyntaxFlow**：逐条关注点，认为没事 / 认为有问题 / 已忽略。
- **Review**：评论卡片，可改可删；每条带引用。

默认打开 AI tab（有摘要时），否则打开 SyntaxFlow。

## 5. 状态

```ts
interface AppState {
  view: 'graph' | 'code';
  rightTab: 'ai' | 'signals' | 'review';
  selected: { kind: 'node' | 'edge'; id: string } | null;
  peek: { open: boolean; nodeId?; edgeId?; file?; line?; side?; function? };
  code: { files; active; mode; layout; line?; side?; search };
  comments; dismissed; kept;
}
```

- 评论/忽略/保留写 `localStorage`，key 是 `intentflow.review:<before>-><after>`。
- 节点选择在图上跨行保留高亮。
- 代码坞高度是组件状态，不持久化。

## 6. 数据流

```text
Go: SSA 一次编译
    → 项目/逻辑/意图事实
    → 行为图（函数调用 + 内部路径）
    → payload.Build（before/after 源码）
    → 可选 LLM 摘要
    → GET /api/payload
React: fetch → layoutFunctionGraph
        ├─ 函数节点合并 + 调用边弹簧布局
        ├─ A* 障碍物寻路 → 绕开卡片
        ├─ 拖拽/滚轮/自动适应
        ├─ 点击函数 → 底部内部行为
        ├─ 点击步骤 → 源码行
        └─ 提交 → POST /api/review → review.md
```
