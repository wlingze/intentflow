# 工作台交互：图、代码、详情，各就各位

> 行为图的语义见 [07-behavior-model.md](07-behavior-model.md)，数据契约见 [08-contract.md](08-contract.md)，
> 评审持久化见 [09-review-platform.md](09-review-platform.md)。

本文描述工作台的目标结构和当前阶段实现。第一阶段只有代码 + Review 视图，
右侧 AI / SyntaxFlow 位置保留但报告「未启用」。后两节描述第二、三阶段要补的部分。

## 1. 问题

旧版把代码放在右侧抽屉。抽屉一开，图被遮住；缩略图浮在代码左下角，又小又挡字。
评论栏在两个视角里都需要，但没有任何一个视角能同时容纳三样东西：

- 这次改动在行为上做了什么。
- 具体哪一行、哪个条件。
- 这条结论的证据和风险。

所以拆成两个主视角，每个视角只保留一个次要视图。

## 2. 当前阶段：代码 + Review

```text
┌──────────────────────── 顶栏（仓库 / 分支 / 范围 / 保存）────────────────────────┐
│ 文件树 可调 │                    diff 卡片列表                    │ Review 面板 │
└─────────────────────────────────────────────────────────────────────────────┘
```

- 页面固定白色，`--bg: #ffffff`；不跟随系统主题。
- 右栏从窗口顶部开始，始终贴住右边；右栏左边缘拖柄可调整宽度。
- 左栏右边缘拖柄可调整整个左栏宽度，范围 200–620px；双击恢复 320px，宽度存 localStorage。
- 左栏拖柄支持 `ArrowLeft` / `ArrowRight` / `Home` / `End`；打开右栏时自动收缩，尽量保证 diff 至少 360px。
- 拖柄支持 `ArrowLeft` / `ArrowRight`，双击恢复 410px。宽度存 localStorage。
- 小于 1000px 时左右栏都变成抽屉；Esc 关闭。

### 2.1 文件树

- 目录可折叠，显示改动数、增删行数；文件行 14px 字号。
- 文件图标按文件名 / 后缀自动选择，使用 `material-file-icons`（Material Icon Theme，377 种，MIT，见 `docs/third-party.md`），覆盖 Go、Markdown、TS/JS、JSON、CSS、Docker 等。
- 目录下的文件全部已查看时，目录名变淡并显示 ✓，与文件行一致。
- 过滤框只过滤路径。
- 文件顺序与 diff 卡片顺序一致：都来自同一个路径排序，不各自重排。
- 底部显示已查看进度。

### 2.2 已查看

两级粒度，都写进评审 JSON：

- 每个 hunk 头右侧有「已查看」勾选，键是 `<file>@<row>#<hunk digest>`。
- 文件级键是 `<file>#<file digest>`。代码内容变化后，旧标记自动失效。
- 文件的「已查看」勾选会一次标记全部 hunk；取消会清空该文件的 hunk 标记。
- 一个文件的全部 hunk 都标记后，文件自动算作已查看，卡片自动折叠。
- 左侧文件树对应行变灰、加删除线，并显示 ✓。
- 目录内每个文件都已查看时，目录行变淡并显示 ✓；任一个取消即恢复。
- 折叠后仍可从卡片头展开；展开不会撤销已查看。

### 2.3 diff 卡片

- 固定卡片头：文件类型图标、目录淡色、文件名加粗、增删行数、已查看。
- 重命名显示为一张卡片：旧路径带删除线，箭头指向新文件名，状态徽标为「重命名」。
- 文件树对重命名行显示 `R`，悬停提示旧路径 → 新路径。
- 计算 hunk 头；折叠区一次展开 5 行，上下各一个按钮。
- 上箭头露出上方行，下箭头露出下方行；文件首尾的折叠区只保留可用的一侧。
- 双击折叠行一次露出整段；卡片头「展开全部」显示整个文件。
- 分栏 / 统一切换；自动换行；全部已读。
- 行虚拟化使用共享滚动容器，视口外只保留占位。
- 卡片正文延迟渲染：只有展开且接近视口（1200px）的文件才计算 diff。
- 卡片离开视口 6000px 后释放正文，长列表保持有界 DOM。
- 卡片使用 `content-visibility: auto`，未进入视口的卡片跳过布局与绘制。
- 服务端对 JSON 与文本响应启用 gzip；12MB payload 传输降到 1.6MB。
- 大范围评审（上千文件）首屏不再一次计算全部文件。

缩进与横向滚动：

- 源码制表位固定为 4 列：`tab-size: 4`。
- 增删标记绝对定位在源码左侧，不参与制表位计算。
- 长行保持 `white-space: pre`。每个文件底部有一条可见横向滚动块。
- 分栏模式左右各一条；拖动时当前文件所有可见行同步滚动。
- 打开「自动换行」后关闭横向滚动，行高自动增长。

### 2.4 评论位置

- 行内评论直接渲染在对应代码行下方，样式比右栏更紧凑。
- 右栏 Review tab 同时列出所有评论。
- 新增评论不强制打开右栏；右栏收起时只在 diff 里显示。
- 左侧文件树在文件名后显示评论数图标，目录显示聚合数。

### 2.5 右侧：AI / SyntaxFlow / Review

三个 tab：

- **AI**：目标形态是 LLM 摘要、优先复核、风险判断。当前没有事实层，显示
  「AI 分析未启用」，并说明评审 JSON 可以从「提交 Review」复制。
- **SyntaxFlow**：目标形态是逐条关注点。当前没有扫描，显示「SyntaxFlow 未启用」。
- **Review**：评论历史的聚合，加一个直接写意见的输入框。没有总结、结论、
  通过 / 请求修改、进度条和底部导出栏。

Review tab 只有两部分：

1. 顶部小输入框，按钮是「增加意见」。正文可以直接粘贴图片。
2. 评论卡片：文件位置、正文、解决 / 修改 / 删除。

分支下其他比较范围留有草稿时，顶部出现一行提示，可一键恢复。
恢复会替换当前比较范围的草稿；行号已失效的意见自动降级为不绑定行号的意见。

右栏默认收起；顶部「评审信息」按钮打开，窄屏用抽屉。
导出入口在顶部「提交 Review」菜单：Markdown / JSON，各自可复制或保存文件。

### 2.6 图片

- 图片直接粘贴进评论正文，渲染时按正文里的 Markdown 图片显示。
- 支持 png、jpg、gif、webp，单张上限 6MB。
- 上传后服务端按内容哈希命名，存 `.intentflow/assets/`。
- 评审 JSON 的正文保存图片 URL，不内嵌 base64。
- 旧数据里的 `images` 字段继续显示，但新评论不再单独存附件。

### 2.7 全局搜索

- `Ctrl+F` / `Cmd+F` 拦截浏览器查找，打开工作台搜索框。
- 页面有选中文本时，选中内容直接成为搜索词；多行选区取第一行。
- 搜索范围是所有文件的 diff 行：新增、删除、上下文和折叠区里的行。
- 结果按文件分组；输入和打开搜索都不会移动代码。
- 新关键词和打开搜索都选最接近当前视口的结果。
- 跳到某条后关闭再打开，代码没动时会停在同一条。
- 按 `Enter` 先跳到选中行；再按 `Enter` 继续下一条。
- `↓` / `↑` 只移动搜索结果选中行，不移动代码。
- `F3` / `Shift+F3` 和上下按钮直接跳上一条 / 下一条；`Esc` 关闭。
- 搜索框右侧有两个开关：`Aa` 区分大小写，`\b` 完整匹配（整词）。
- 两个开关独立：可只区分大小写，也可只匹配整词；默认都关闭，按子串、忽略大小写。
- 开关记在 localStorage；关闭搜索、刷新页面都保留。
- 结果按 diff 类型着色：新增绿、删除红、上下文灰；新增和删除的行首有同色标记，类型徽标同色。
- 文件分组头显示该文件的类型图标。
- 点击结果跳到对应文件行；折叠文件自动展开，目标行显示左侧琥珀色定位条。
- 搜索框关闭时按 `F3` 也会打开搜索。
- 右上角放大镜按钮提供同样入口，移动端可用。

### 2.8 单词高亮

- 单击代码里的标识符，所有 diff 文件中的同名单词加上蓝色高亮。
- 精确匹配、区分大小写；数字、关键字、注释和字符串里的同名单词也会高亮。
- 再次点击同一个词、点击代码空白处或点击另一个词会切换 / 清除。
- 拖选复制文本时不触发高亮。
- 高亮只作用于当前页面，不写入评审 JSON。

### 2.9 代码选区

- 从任意一行拖到另一行即可选区，含行号、增删号区域。
- 选区按行着色，整行显示蓝色左边条；拖出视口时自动滚动。
- 分栏模式只选拖动起点所在的一侧；统一模式按行顺序选取。
- `Ctrl+C` / `Cmd+C` 复制选中行，文本只含该侧的代码。
- 点代码里的单词会清除选区；`Esc` 或点击 diff 外也会清除。
- 有选区时在选区末行点 `+`，评论引用改成多行区间。
- 有选区时按 `Ctrl+F`，搜索框填入选区首行。

### 2.10 符号引用

- 左栏下半部分是「符号」面板，默认展开，可折叠；展开状态存 localStorage。
- 点击 diff 里的标识符，或直接在面板输入，列出当前 diff 中该词的全部引用。
- 面板没有输入框；符号只来自点击代码里的标识符，`×` 清除。
- 面板头有两个开关：`Aa` 区分大小写，`\b` 完整匹配；默认都开启。
- 符号面板和搜索框的开关各自独立保存。
- 面板高度可拖顶部横条调整，双击恢复 300px；高度存 localStorage，范围 120px 到左栏底部留 150px。
- 与全局搜索共用同一匹配和行内容；同样按新增 / 删除 / 上下文三色显示。
- 点击一行跳到对应文件行；折叠文件自动展开。
- 面板输入与代码单词高亮共用同一个词，输入时 diff 同步高亮。
- 结果超过 200 行时显示「显示更多」。

### 2.11 行内改动标记

- 同一对增删行里，只有真正变化的词加底色，与 GitHub 的行内 diff 一致。
- 增删块按内容配对：相似的行排在同一行，不按位置硬配。
- 新增侧用深绿底（`--chg-add`），删除侧用深红底（`--chg-del`），不加描边。
- 正文对比度保持 ≥ 6.9:1；未变化的词保持普通代码底色。
- 空白差异不标记：只改空格或缩进时不加底色。
- 单行超过 320 个词或 4000 字符时退化为「去掉公共首尾」，不再逐词比对。
- 退化后仍出现过宽标记（单个标记超过 40 字符）时同样改用首尾裁剪。
- 词级标记与语法着色叠加显示；点击单词的选中高亮也保留。

### 2.12 卡片高度与虚拟行

- 没有自动换行时行高固定：代码行 22px、hunk 头 26px、折叠区 32px。
- 虚拟滚动用这组固定高度做初值，卡片高度不再等测量后才收敛。
- 离视口 2000px 外的卡片只渲染等高占位块，不渲染行。
- 占位块高度等于真实正文高度，所以滚动时文档总高不变，下方文件不会跳动。
- 卡片进入 2000px 范围后挂载真实行，并按固定高度逐行测量校正。
- 换行模式下行高按字符数估算，挂载后由测量覆盖。

### 2.13 跳转

- 跳转分两步：先把目标卡片滚进视口，再由卡片在挂载后对齐具体行。
- 卡片不挂载正文时占位块高度不变，所以滚动容器总能一次滚到位。
- 搜索、符号、评论、文件树四种入口共用这条路径。
- 目标行最终落在视口内，并留出搜索面板的高度。

### 2.14 评审状态存放

- 评审 JSON 存在浏览器 localStorage，键为 `intentflow.review.<comparison_id>`。
- 服务端默认不写 `.intentflow` 目录；`--review-dir` 留空即纯内存。
- 需要落盘时显式传 `--review-dir`，行为与旧版本一致。
- 评论图片内联为 data URL，随文档一起存在浏览器；单张上限 1.5MB。
- 「其他草稿」列表与恢复也走浏览器存储。
- 导出入口不变：顶部「提交 Review」复制 Markdown 或保存 JSON 文件。

### 2.15 文件树当前状态

- 正在 diff 面板里显示的文件用灰色行底标记。
- 从文件树、搜索或符号面板点开的文件用蓝色行底和蓝色左边条标记。
- 蓝色优先于灰色：同一个文件既在屏上又是当前文件时显示蓝色。
- 屏内文件与挂载范围由一个观察器统一维护，避免每张卡片各建观察器。

## 3. 状态

`AppProvider` 只保留：

- `payload` / `loading` / `error` / `revisions` / `revisionId`
- `comments` / `viewed` / `reviewedHunks`
- `saveStatus` / `saveError`
- `panels` / `rightTab` / `drawer`
- `code`（布局、换行、定位）

每次评论或已查看变化，`editVersion` 加一。400ms 防抖后 PUT
`/api/review/state`。保存串行执行，避免旧请求覆盖新状态。保存失败时停在错误
状态，不自动重试；按钮可手动重试。

切换比较范围前，如果还有未保存修改，先等待保存完成。加载期间 diff 和右栏
设为 `inert`，防止把评论写到旧范围。

## 4. 目标阶段二、三：行为图与代码联动

以下结构在接回 SSA 事实层后启用。

```text
┌──────────────────────────────────────────────────────────────┐
│ top bar: branch labels · stats · 行为图/代码 · 提交           │
├────────────┬──────────────────────────────────┬──────────────┤
│ 项目改动   │ 函数调用关系图                    │ AI /         │
│ 目录树     │ 拖拽/缩放/适应                    │ SyntaxFlow / │
│ +文件      │ 点函数 → 下边栏内部路径           │ Review       │
│            ├──────────────────────────────────┤              │
│            │ 内部行为: 触发→判定→变换→效果     │              │
│            │ 右栏: 对应源码                     │              │
└────────────┴──────────────────────────────────┴──────────────┘
```

- 一屏只画函数调用；节点位置由调用边决定，不按文件框顺序排列。
- 边用障碍物网格寻路，绕开节点；标签悬停显示。
- 点函数展开内部行为路径；点步骤跳到源码行。
- 删除悬浮缩略图；画布本身可拖拽、缩放、适应。

## 5. 交互约束

- 不做「认为有问题」之类的隐性判断；评论就是唯一动作。
- 行号不是跳转入口，只用于定位评论。
- 不做跨文件搜索或符号图；第一阶段工作台只服务一次 diff 评审。
- 折叠区没有「展开全部」，避免大文件瞬间展开。
- 不在页面上显示扫描进度或 AI 状态；未启用的 tab 直接说明原因。

## 6. 验证

- `make check` 通过：`go vet`、Go 测试、`tsc`、前端单测。
- Playwright 1440：右栏 `x + width = 1440`、`y = 0`；拖动、键盘调整、双击复位正常。
- 制表位：连续两个 Tab 渲染宽度等于 8 个空格；`tabSize = 4`。
- 长行：滚动块可拖动，代码同步偏移。
- 评论新增、修改、解决、删除、Markdown / JSON 导出、重启恢复均通过。
- 不绑定文件的意见也能保存和恢复；图片粘贴后以 Markdown 写进正文。
- 1440、800、390 三种宽度无页面横向溢出；控制台零错误。
