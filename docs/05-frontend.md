# 工作台交互：图、代码、详情，各就各位

> 行为图的语义见 [07-behavior-model.md](07-behavior-model.md)，数据契约见 [08-contract.md](08-contract.md)。

## 1. 问题

旧版把代码放在右侧抽屉。抽屉一开，图被遮住；缩略图浮在代码左下角，又小又挡字。评论栏在两个视角里都需要，但没有任何一个视角能同时容纳三样东西：

- 这次改动在行为上做了什么。
- 具体哪一行、哪个条件。
- 这条结论的证据和风险。

所以拆成两个主视角，每个视角只保留一个次要视图。

## 2. 图视角：三级图 + 节点放大

```text
┌──────────────────────────────────────────────────────────────┐
│ top bar: branch labels · stats · 行为图/代码 · theme · 提交   │
├────────────┬──────────────────────────────────┬──────────────┤
│ 项目改动   │ 文件 | 函数 | 行为               │ AI /         │
│ 目录树     │                                  │ SyntaxFlow / │
│ +文件      │ 可拖拽/缩放的图                   │ Review       │
│            │ 点节点 → 放大卡片                 │              │
│            ├──────────────────────────────────┤              │
│            │ 节点详情 + 源码（展开代码后）     │              │
├────────────┴──────────────────────────────────┴──────────────┤
│ composer                                                     │
└──────────────────────────────────────────────────────────────┘
```

### 2.1 三级图

| 层级 | 节点 | 边 | 用途 |
| --- | --- | --- | --- |
| 文件 | 行为路径涉及的文件，节点聚合函数数量 | 文件之间的行为关系 | 先看改动落在哪些文件 |
| 函数 | 按函数身份合并角色节点，按文件分组 | 函数调用/数据关系 | 看调用方向和跨文件关系 |
| 行为 | 同源 scenario 合并成组，组内保留判定 | 控制边、数据边、调用边 | 看 `if`/`switch` 和数据形态 |

- 文件层不展开函数内部；函数层按文件画分组框；行为层才出现判定节点。
- 同一个函数在触发/变换/效果里出现多次时，函数层合并为一个节点，并标角色数量。
- 行为层按触发函数分组；同一入口的多条 scenario 不再各占一行。
- 默认停在函数层。文件层适合先看宏观，行为层适合追一条路径。

### 2.2 画布与节点放大

- 画布支持拖拽平移、滚轮缩放、`适应` 看全图。
- 画布使用固定视口，内容超出时平移；不把整张图压到屏幕里。
- 点击节点打开右上角放大卡片：文件、行号、函数、形态、来源、角色、证据。
- 卡片里的「展开代码」打开底部代码坞；「打开文件」切到代码视角。
- 文件节点没有具体函数行，展开代码时显示文件上下文。

### 2.3 底部代码坞

节点详情坞只在点击「展开代码」或点到边时出现：

- 左栏：角色、delta、文件行号、函数、来源、形态、所属 scenario、证据。
- 右栏：目标行前后 6 行源码，目标行高亮。
- 「引用到评论」把这段代码加入 composer。
- 「打开代码」切到代码视角并定位。
- 顶部有拖拽条，可调高度；右侧关闭按钮收起。

点击节点本身只放大节点信息，不自动打开代码。这是「点击看信息、按钮再展开代码」的分工。

### 2.4 项目改动树

左栏是目录树，不是平铺事实列表。

- 目录显示聚合 `+行数 / −行数 / 变更文件数`。
- 顶部有增/改/删的构成条。
- 默认只看变更文件；可以切换全部。
- 结构事实和调用事实的数量写在标题下方，供宏观判断。

## 3. 代码视角

```text
┌──────────────────────────────────────────────────────────────┐
│ top bar                                                      │
├────────────┬──────────────────────────────────┬──────────────┤
│ 行为导航   │ 文件 tab · Diff/搜索 · 分栏/统一 │ AI /         │
│ 01 flow    │                                  │ SyntaxFlow / │
│ 02 flow    │ 全宽 diff / 搜索                 │ Review       │
├────────────┤                                  │              │
│ 变更文件   │                                  │              │
├────────────┴──────────────────────────────────┴──────────────┤
│ composer                                                     │
└──────────────────────────────────────────────────────────────┘
```

- 左上是行为导航：按触发函数分组；组内展开同源 scenario，点步骤直接跳到文件行。
- 左下是变更文件树；不再重复项目结构事实。
- 没有悬浮缩略图。行为图就是侧栏里的流程列表。
- 选中代码 → 浮动「添加评论」→ 引用进入 composer。

## 4. 右侧：AI / SyntaxFlow / Review

三个 tab：

- **AI**：LLM 摘要、优先复核、风险判断。状态为 `ok` 时显示；未配置时显示环境变量说明。LLM 只读事实。
- **SyntaxFlow**：逐条关注点，认为没事 / 认为有问题 / 已忽略。
- **Review**：评论卡片，可改可删；每条带引用。

默认打开 AI tab（有摘要时），否则打开 SyntaxFlow。

## 5. 状态

```ts
interface AppState {
  view: 'graph' | 'code';
  rightTab: 'ai' | 'signals' | 'review';
  selected: { kind: 'node' | 'edge'; id: string } | null;
  peek: { open: boolean; nodeId?; edgeId?; file?; line?; side? };
  code: { files; active; mode; layout; line?; side?; search };
  comments; dismissed; kept;
}
```

- 评论/忽略/保留写 `localStorage`，key 是 `intentflow.review:<before>-><after>`。
- 节点选择在图上跨行保留高亮。
- 代码坞高度是组件状态，不持久化。

## 6. 数据流

```text
Go: SSA 一次编译
    → 项目/逻辑/意图事实
    → 行为图（scenario 行）
    → payload.Build（before/after 源码）
    → 可选 LLM 摘要
    → GET /api/payload
React: fetch → layoutFileGraph / layoutFunctionGraph / layoutBehavior
        ├─ 文件层 → 文件聚合图
        ├─ 函数层 → 按文件分组的函数图
        ├─ 行为层 → 同源 scenario 合并行
        ├─ 拖拽/滚轮 → 平移/缩放
        ├─ 点击节点 → 放大卡片
        ├─ 展开代码 → 底部代码坞 → 代码视角
        └─ 提交 → POST /api/review → review.md
```
